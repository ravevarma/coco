# ADR 0011 — ACPI parsing policy

**Status:** accepted (M2)

* Parsing lives in `coco-acpi`: no allocation, no `unsafe`, all arithmetic
  checked, every read through a fallible `PhysMemory` trait. The kernel
  supplies memory by mapping table pages read-only into the direct map on
  demand (firmware tables may sit outside RAM regions).
* **Checksums are enforced.** A table with a bad checksum is rejected and
  counted, not trusted. This may lose features on firmware with broken
  tables; that trade-off favours safety and is revisited only with
  evidence from real hardware.
* Fixed upper bounds: 4 MiB per table, 256 root entries, 256 CPUs, 16 I/O
  APICs, 32 overrides (overflow is counted, not stored).
* `\_S5` is located by a targeted AML pattern match
  (`NameOp "_S5_" PackageOp`), not an AML interpreter. Platforms that
  define `_S5` through methods cannot power off yet.
